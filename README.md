# BH Explorer — municipality guessing game

Name the 142 municipalities of Bosnia and Herzegovina from memory. Each correct
name is revealed on the map. Play the whole country, one entity, or a single
canton. Available in Bosnian, Croatian, Serbian and English; the map pans and
zooms.

```bash
npm install
npm run dev        # dev server
npm run typecheck  # tsc --noEmit
npm test           # vitest
npm run build      # typecheck, then build
```

TypeScript throughout, strict, with `noUncheckedIndexedAccess`.

## How the code is arranged

The rule is one direction of dependency: **data → domain → hooks → components**.
Nothing in `domain/` imports React, and nothing in `components/` contains a game
rule. That is what makes the tricky parts testable without a browser.

| Folder | Holds | Imports from |
| --- | --- | --- |
| `src/types.ts` | Geometry aliases: `Box`, `ViewBox`, `Point`, `Size` | nothing |
| `src/data/` | Raw facts: boundary geometry, the canton and entity lists | nothing |
| `src/domain/` | Pure logic: name matching, scoring, scope maths, geometry | `data/` |
| `src/i18n/` | Locale catalogues, the translator, and name rendering | `data/`, `domain/` |
| `src/hooks/` | React state built on that logic | `domain/` |
| `src/components/` | Presentation only | `hooks/`, `i18n/`, `domain/` |

### `src/data/`

- `municipalities.json` — 142 records as positional tuples, generated by
  `npm run build:data`; do not hand-edit. The key names would outweigh the
  payload at this size, so the shape is declared once, as the
  `MunicipalityRow` tuple type in `domain/municipalities.ts` — the only file
  that reads the layout.
- `cantons.ts`, `entities.ts` — the administrative units. Canton `no` is the
  official constitutional ordinal, not a display index.

### `src/domain/`

- `text.ts` — folds any spelling to one key. Strips diacritics and
  transliterates Cyrillic, so `zepce`, `Žepče` and `Жепче` all match.
- `answers.ts` — the answer index and `checkGuess`, a pure function that judges
  a guess against round state. Two rules live here and are worth knowing:
  - a name shared by **two** municipalities stays playable (Trnovo and Kupres
    each exist in both entities — name it twice);
  - a name shared by **more than two** is rejected as too broad. Without this,
    "Sarajevo" — an alias on all eight Kanton Sarajevo municipalities — hands
    over the whole canton for one word.
- `scope.ts` — what a round covers and how it is tallied by region.
- `geo.ts` — bounding boxes, viewBox framing, and projecting a map point to a
  pixel. No projection maths: the source artwork is already projected.

### `src/i18n/`

Four locales: `bs`, `hr`, `sr`, `en`. Bosnian, Croatian and Serbian are separate
entries, not one "BCS" option — all three are official in Bosnia and
Herzegovina, they differ in words this interface actually uses (*obuhvata* /
*obuhvaća*, *tačni* / *točni*), and Serbian is written here in Cyrillic.

- `locales/en.ts` — the source of truth. Its keys become `TranslationKey`, and
  the other three catalogues are typed `Record<TranslationKey, Phrase>`, so a
  missing or misspelled key is a compile error rather than a silent runtime
  fallback. `t("result.agian")` does not build either.
- `index.ts` — the catalogue registry, browser-language detection, and
  `createTranslator`. Plural category comes from `Intl.PluralRules`, so Slavic
  one/few/other is the platform's problem rather than a hand-rolled modulo rule.
- `LanguageProvider.jsx` — the context. Alongside `t()` it exposes `place()`,
  `region()` and `scopeName()`, because names need more than a lookup: place
  names are stored in Latin only and are transliterated for Serbian, while
  regions have their own English forms.

Two consequences worth knowing:

- **Feedback is stored as a key, not a sentence.** `useGameRound` emits
  `{ key, values, municipality }` so the last message re-renders when the player
  switches language mid-round.
- **Transliteration never affects play.** Answers were already script-agnostic,
  so a Latin guess still scores while the board is in Cyrillic.

### `src/hooks/`

- `useGameRound.ts` — the whole game as one hook: scope, found set, clock,
  feedback. Components read from it and never compute a rule themselves.
- `useMapNavigation.ts` — pan, zoom and the eased flights between rounds, in one
  value. The view normally follows the frame the round implies; the moment the
  user drags, pinches or scrolls it becomes theirs and stops chasing, until the
  round changes or they reset. Wheel is bound by hand because React's `onWheel`
  is passive and so cannot stop the page scrolling.
- - `useElementSize.ts`, `useReducedMotion.ts`, `useRoundClock.ts` — one job each.

### `src/components/`

Each component sits beside its own `*.module.css`. Shared primitives
(`.block`, `.label`, `.btn`) and the token palette are global, in
`src/styles/`.

`MapStage` is the only component with real logic, and it is all view logic:
turning game state into a per-shape status, framing the map, and placing the
callout.

## What TypeScript is actually doing here

Beyond the usual: the domain types make the awkward parts of this app
self-documenting. `Box` is `[x0, y0, x1, y1]` and `ViewBox` is
`[x, y, width, height]` — two four-number tuples that were previously easy to
pass to the wrong function. `ScopeKind`, `EntityId` and `CantonCode` are unions,
so an invalid round is unrepresentable. And the locale catalogues check
themselves, which replaced a runtime test with a build error.

CSS Modules are the one place the compiler cannot help: `styles.typo` is
`undefined` and renders an unstyled element. `tests/styles.test.ts` stands in
for that, checking every `styles.*` reference, global utility class and custom
property against the stylesheets.

## Two details that are easy to break

**Unfound shapes must stay anonymous.** `MapStage` attaches no tooltip and no
click handler to a `todo` shape. Adding either would let a player read answers
off the board.

**Typing scores on its own, but not always.** A value fires the moment it can
only mean one place. "Novi Grad" is a municipality *and* the opening of "Novi
Grad Sarajevo", so it waits for Enter. That is `firesOnType` in `answers.ts`.
Exactly five names are in that position — Doboj, Foča, Kupres, Novi Grad and
Pale — and a test pins the list, so an added alias cannot quietly make a sixth
name feel broken.

**A drag must not also be a click.** `useMapNavigation` tracks how far the
pointer travelled and `MapStage` checks `nav.dragged()` before selecting a
shape, or every pan that ends over a municipality would reselect it.

**The zoom-out ceiling includes the padding.** `limits.maxWidth` is computed
from the *padded* country box. From the unpadded box it comes out narrower than
the default country view, which then gets silently cropped.

**A scrolling grid item needs `min-height: 0`.** Grid items default to
`min-height: auto` and refuse to shrink below their content, so `overflow-y`
never engages. Without it the rail's end-of-round content — a result card plus
up to 141 "missed" chips — stretched the whole row, the map stretched with it,
and its aspect collapsed. That read as the map zooming out and then refusing to
pan or zoom back. `tests/styles.test.ts` guards it, because jsdom has no layout
engine and cannot catch it by rendering.

**"Zoom to X" is a one-shot, not a mode.** It calls `nav.flyTo`, which hands
control to the user. When it was a persistent flag, every later correct guess
changed the frame it pointed at and yanked the map across the country.

## Tests

```bash
npm test
```

Two suites, split along the same seam as the code:

- `tests/answers.test.js` — the matching rules, with no DOM at all. Every case
  in the "too broad" and "shared name" rules is pinned here, plus a check that
  all 142 municipalities stay reachable by at least one spelling.
- `tests/App.test.tsx` — the game through the rendered UI, queried by role and
  label. The map is the one exception: each shape carries `data-status`
  (`found` / `missed` / `todo` / `out`) so counting the board never depends on
  class names.
- `tests/i18n.test.tsx` — transliteration against every place name, catalogue
  completeness, Slavic plural forms, and switching language mid-round.
- `tests/navigation.test.tsx` — the viewBox maths, then drag, pinch, keyboard
  and the drag-versus-click rule through the UI, plus a `regressions` block
  pinning the two map bugs above.
- `tests/styles.test.ts` — the checks the CSS Modules types cannot make.

`tests/setup.ts` reports `prefers-reduced-motion`, which collapses the viewBox
easing to a single step and keeps assertions deterministic.

## Where the boundaries come from

**geoBoundaries** (William & Mary geoLab), CC BY 4.0. Full attribution, the
citation and the list of modifications are in
`scripts/geoboundaries/ATTRIBUTION.md`; the app credits it in its footer in
every language.

`src/data/municipalities.json` is generated, not authored:

```bash
npm run build:data
```

`scripts/build-municipalities.mjs` reads ADM3 for the shapes and ADM2 for the
grouping. geoBoundaries carries **no parent link** in its properties — an ADM3
feature knows its own name and nothing else — so each municipality is assigned
to a canton by sampling its interior and taking the region that covers most of
it. A single centroid is not enough: on a concave border it can land in a
neighbour.

The script also refuses to write if a municipality present in the last build
has disappeared, which is how a bad release gets caught rather than quietly
shrinking the game.

Three defects in the source are corrected in the build and pinned by tests —
one municipality is filed under an entity's name, one is misspelled, and one is
placed in the wrong canton. `ATTRIBUTION.md` explains each.

**Known gap:** Stanari (RS, formed 2014) is absent from this release, so a full
round counts 142 municipalities rather than the current 143.
